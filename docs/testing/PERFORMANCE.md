# Производительность и стабильность

Измерено 4 ноября 2026 на компьютере разработчика (Windows 11) и в GitHub Actions. Скрипты измерений лежали во
временной папке сессии и в репозиторий не входят; повторяемые проверки — в тестах.

## Построение экранов

Каждый экран строится из данных сезона 2026 (заглушка Flet, без отрисовки).

| Что | Медиана |
|---|---|
| Главная (`tab0`) | 55 мс |
| Остальные вкладки и подэкраны | 0.3–17 мс |
| Загрузка состояния из базы (`state.load`) | 79 мс |
| Память за 5700 построений | +4.2 МБ (в основном заглушка Flet) — утечки не видно |

Статус: **Passed**. Главная — самая тяжёлая. Тормозов это не даёт, но если экран будет расти, первым кандидатом
на кэш будет она.

## База под нагрузкой

6 потоков в течение 30 с: избранное, настройки, чтение зачёта при непрерывном обновлении.

| | До исправления | После `e1f5dbc` |
|---|---|---|
| IntegrityError | 31 | 0 |
| Операций дольше 1 с | до 9 (под непрерывным обновлением) | до 9 |

Статус: ошибки — **Passed**. Задержки до 1 с при непрерывной записи — **Needs Review**: это ожидание блокировки
SQLite (timeout 10 с), а не сбой. Пользователь при обычном обновлении раз в 5 минут их не встречает.

## Сеть с ошибками

Ответы подменялись в процессе: медленный, HTTP 500, 429, HTML вместо JSON, обрезанный, 60 МБ, неверные типы,
сброс соединения.

| Результат | Статус |
|---|---|
| Исключений нет, приложение остаётся на данных из базы с пометкой «Из кэша» | Passed |
| Медленный ответ обрывается по тайм-ауту (8 с) | Passed |
| После восстановления сети данные обновляются | Passed |
| Огромные ответы картинок и радио читаются не дальше предела (с `f218d3e`) | Passed |
